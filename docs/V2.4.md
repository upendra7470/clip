# Clip v2.4: Clipboard Watch OCR

Clip v2.4 adds an always-ready local OCR workflow for screenshots and images copied from any application.

## Command

```sh
clip --watch
```

While the command is running, copying an image triggers offline OCR. The recognized text replaces the image on the clipboard, and Clip continues waiting for the next image. `Ctrl+C` stops the watcher cleanly.

Existing output controls compose with watch mode:

```sh
clip --watch --smart
clip --watch --layout exact
clip --watch --format markdown --rich
clip --watch --format json --stdout
```

`--watch` does not accept a filename and cannot be combined with file-input modes, directory recursion, chunks, or `--output`. Use `--stdout` for a stream of recognized results instead of replacing the clipboard.

## Privacy and resilience

- OCR remains entirely local.
- Clipboard items marked sensitive by the source application are skipped.
- Images are normalized by the native clipboard layer and bounded by Clip's input-size and decoded-image safety limits.
- Private temporary PNG files are removed immediately after each OCR attempt.
- Duplicate clipboard notifications are suppressed using an in-memory SHA-256 digest.
- An unreadable image produces a warning without terminating watch mode.

## Platform behavior

The implementation uses Clip's existing native clipboard backend on Windows, macOS, X11, and Wayland. It does not poll the filesystem, invoke a shell utility, or require a background service. The process exists only while the user is running `clip --watch`.
