# Clip v2.7: OCR Intelligence

Clip v2.7 adds an adaptive recognition pipeline for difficult scans:

```sh
clip --enhance difficult-scan.png
```

## How enhancement works

One input produces several private OCR candidates:

1. Validate decoded dimensions and pixel count before preprocessing.
2. Convert to grayscale and stretch low-contrast tonal ranges.
3. Produce an Otsu-binarized candidate, automatically inverting light-on-dark scans.
4. Estimate text-line skew from horizontal ink projections and correct meaningful angles up to three degrees.
5. Recognize each candidate and retain the result with the strongest readability score.
6. Test the strongest candidate at 0°, 90°, 180°, and 270° to correct page orientation.
7. Send the winning text through Clip's layout and output pipeline.

The readability score rewards letters, numbers, whitespace, normal punctuation, and word-like tokens while penalizing control characters, replacement characters, and punctuation-only noise.

## Every OCR entry point

`--enhance` composes with all OCR workflows:

```sh
clip --image --enhance receipt.jpg
clip --pdf --enhance --layout exact scanned.pdf
clip --screen --enhance --rich
clip --clipboard --enhance --stdout
clip --watch --enhance --format markdown
clip --auto --enhance
clip --make-searchable --enhance archive.pdf
```

It also works with `--smart`, language hints, structured formats, chunks, rich clipboard output, stdout, and file destinations where those controls are normally supported.

## Local-first safety

- Enhancement uses Go image processing built into the Clip executable.
- No ImageMagick, OpenCV, Python, OCR API, or network service is required.
- The existing 20,000-pixel dimension and 100-million-pixel decoded-image limits apply before processing.
- Enhanced preprocessing uses the stricter 25-million-pixel working limit.
- All recognition passes share the existing two-minute OCR deadline.
- Candidate images are created with private temporary-file permissions and removed on success, failure, or cancellation.

## Scope

v2.7 improves printed-text recognition using the bundled Latin-script model. Additional script model packs and handwriting recognition remain future capabilities because they require separately trained and validated recognition assets; `--enhance` does not pretend that preprocessing can replace those models.
